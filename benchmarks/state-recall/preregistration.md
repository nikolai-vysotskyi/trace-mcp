## Why this exists

The Phase-4 SKILL.state A/B reported −66.8% prompt tokens, −59.2% total, and
**Pass@1 100% in both arms** over 18 pinned tasks. Equal success at a ceiling is
not evidence that compression is free — it is evidence that nothing in that
harness was hard enough to get wrong. `state-benchmark.ts` is a closed-form
token model and `state-trace-replay.ts` measures prompt cost on real sessions;
neither has a task to succeed or fail at.

TRA-568 is what happens when a claim of this shape is finally checked: the
context-packing arm came out 15 points *worse* at understanding the change.
Catching the same defect in the state loop costs nothing if we look for it.

## Task

Long-horizon fact retention. Twelve synthetic tasks, twenty turns each. Each
turn hands the agent a tool result; six of them additionally carry a planted
fact — a constraint, a dead end, or a concrete detail — each tagged with a
distinctive `ALL_CAPS_1234` literal. Facts land in the first 60% of the run.
At the end the agent is asked to report what the session established.

Corpus: `corpus.json`, generated by `generateTasks({ taskCount: 12,
turnsPerTask: 20, factsPerTask: 6, seed: 1115 })` — deterministic, regenerate
with `tsx scripts/bench-state-recall.ts --generate`.

## Grading

Exact match on the planted literal. A fact counts as retained only if its code
is quoted back; paraphrase does not count. No judge model, so the grader cannot
drift between arms or between runs.

- `recall` — share of the six facts retained.
- `pass_rate` — share of tasks where all six were retained (this is Pass@1).
- `fabricated_per_task` — `ALL_CAPS_1234` codes quoted that were never planted.

## Arms

| Arm | Prompt | Can it fail? |
|---|---|---|
| `full` | whole 20-turn transcript, no budget | Only by careless reading. This is the ceiling. |
| `truncated` | transcript trimmed to the budget, oldest turns dropped first | Yes — early facts are physically absent. |
| `state` | goal + a model-rewritten compact state block + the last 2 turns | Yes — a fact not written into state is gone permanently. |

The `state` arm spends one model call per turn rewriting its state block, then
one to answer. The other two spend one call each. That cost asymmetry is real
and is reported, not netted out.

## Budget

**4500 tokens.** Chosen mechanically before any call, from the corpus alone:
it is the setting where the truncated arm keeps 13.8 of 20 turns and **43.1% of
planted facts remain visible to it**. Lower budgets make the baseline a
strawman (3500 → 15.3% visible; 2500 → 0%), higher ones stop biting.

That 43.1% is the truncated arm's mechanical ceiling and is written into
`results.json` as `truncated_visible_ceiling`. Its recall must never be read as
a model failure without subtracting it.

## Hypotheses and thresholds

**H1 — the failure mode is real.** `truncated.recall` < 0.60. If truncation at a
budget this generous costs nothing, the harness is not testing retention and
the whole run is void.

**H2 — state beats truncation.** `state.recall` ≥ `truncated.recall` + 0.20.
This is the claim the architecture makes. Below +0.20 the state block is not
buying enough to justify a model call per turn.

**H3 — the honest one: state does not lose to the full transcript.**
`state.recall` ≥ `full.recall` − 0.10. This is the TRA-568 threshold, same
tolerance. **A miss here is the finding**, and it publishes: it would mean the
state loop drops what the agent needed, exactly as our packer was shown to.

**H4 — no invention.** `state.fabricated_per_task` ≤ `full.fabricated_per_task`
+ 0.5. Rewriting facts from memory rather than copying them out of a transcript
is where a hallucinated identifier would come from.

Secondary, not gated: recall split by fact kind. `detail` facts are the ones a
compact state has the least reason to keep. If state loses, expect it to lose
there first.

## What may be published

Nothing from this run goes on a public surface unless H1 holds — without a real
failure mode the numbers say nothing. If H1 holds, every result publishes,
including a failed H2 or H3, and the token half of the SKILL.state claim
publishes only alongside whatever this says about quality.

## Known ceilings

- The corpus is synthetic. Real sessions would be better evidence, but no
  corpus labels "which facts did this session still need at turn 40" and our own
  sessions carry no success labels. Upgrade path: replace `generateTasks` with
  mined sessions once TRA-1090's harness has per-fact labels.
- One model (`claude-sonnet-4-5`), reached through the `claude` CLI in headless
  mode because this runtime has no API key. The CLI's own system-prompt overhead
  is a constant identical in all three arms; absolute prompt-token figures here
  are the harness's estimate, not the provider's bill.
- Exact-match grading undercounts a correct answer that paraphrases. It
  undercounts every arm equally.
- Twelve tasks is a pilot. It can show a large effect and cannot resolve a small
  one.
